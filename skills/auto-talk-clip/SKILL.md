# 草稿目录自动剪辑 + 封面（auto-talk-clip）

把 `草稿待剪辑/` 的口播视频批量剪成片、配封面，结果放 `剪辑后的成片/`，Excel 按哈希记账，重复运行只处理新增的。

## 目录结构（每条视频独立文件夹）

```
E:\自媒体\剪辑后的成片\
  石头工具箱\
    一天一个强大的网站介绍\          <- 视频独立文件夹（命名=视频文件名，规则待用户定）
      一天一个强大的网站介绍.mp4      <- 剪好的成片
      字幕.srt                       <- 烧进画面的同一份字幕
      封面_横屏.png                  <- 1920x1080
      封面_竖屏.png                  <- 1080x1920
      封面_视频号个人页3-4.png       <- 1080x1440（微信视频号个人主页卡片）
      封面_视频号分享4-3.png         <- 1440x1080（微信视频号分享卡片）
  剪辑记录.xlsx                      <- 去重记账表
  封面文案清单.json                  <- 封面标题/副标题（Agent 填写）
  .auto-clip-anchor\                 <- 批次锚工程（内部）
```

## 能剪到什么程度（边界，必须对用户讲清）

全自动 = **本地 Whisper 转写 + 字幕烧进画面 + 暗金科技标题动画 + 导出**。
按工作台铁律：全自动**不删口误、不停顿、不做 FredTalk/自由创意包装**，成片标记「未人工听看」。要精细粗剪或创意包装，明确告知需走口播工作台逐条人工审看。

## 执行流程：三段式（必须按顺序）

### 第 1 段 · 自动剪辑（脚本）
```
python "E:\自媒体\skills\auto-talk-clip\scripts\auto_clip.py" --dry-run   # 先看清单
python "E:\自媒体\skills\auto-talk-clip\scripts\auto_clip.py"              # 正式剪辑
```
扫描 → SHA256 查表判重 → 未剪的走 `batch-create(auto,remotion-gold)` → `batch-add` → `batch-enqueue auto` → `batch-run` → 成片+字幕落进各自独立文件夹 → Excel 追加行 → 写/更新 `封面文案清单.json`（新视频标题/副标题留空，附字幕预览）。
参数：`--limit 1` 试跑、`--force` 强制重剪、`--packaging none` 只烧字幕、`--draft/--out` 换目录。

### 第 2 段 · Agent 写封面文案（我来做）
读 `封面文案清单.json` 里每条的「字幕预览」或视频文件夹里的 `字幕.srt`，**根据视频内容判断**标题和副标题，填回去：
- `标题`：主标题，`|` 分行（如 `宅家也能|逛遍全世界?`），1~2 行、每行尽量 ≤8 字。
- `副标题`：黄条上的一句话（如 `一个网站 带你云开车看街景`），简短点题。
- 空白的条目会在第 3 段被跳过。标题风格参考 `E:\自媒体\封面\参考封面\`。

### 第 3 段 · 生成封面（AI 生图，当前默认）

**由 Agent 逐条调用生图能力，不是脚本一键批量跑**（生图无本地脚本接口，且每张必须人工核字）。

调用参数：
- `image1 = assets/风格锚_参考封面.png`，`image2 = assets/人物锚_参考封面半身.png`
- `input_fidelity=high`、`quality=high`
- 横版 `size=1536x1024`；竖版/两种卡片**各自单独生图**（`size=1024x1536` 方向），**禁止从横版裁剪**——会裁掉人像，这正是用户当初否定"一张图裁剪"的原因。

提示词模板（`{标题}` 由清单填入，`|` 换成换行/空格；`{版式}` 按方向替换）：
```
以第一张参考图为海报风格与构图基准，重新设计一张 {版式} 科技自媒体视频封面。
严格要求：画面中的人物必须是参考图里同一位男子，保持完全相同的面部特征、黑色短发、
灰色半框眼镜、亮黄色圆领T恤和右手食指向上指的姿势，不得换成其他人的长相或改变五官。
人物半身像位于画面{人物位置}，面带生动讲解表情，轮廓带淡淡蓝色辉光，与背景自然融合，
摄影级真实高清。背景：深蓝色科技感工作室，柔和蓝橙氛围灯，虚化书架绿植与显示器，
点缀发光灯泡、齿轮、电脑、柱状图等蓝色线性科技图标，右上方一个明亮发光黄色灯泡。
文字（完全忽略参考图里的旧中文，全部换成以下新文案）：{标题区描述}主标题「{标题}」，
白色字芯，带深蓝色与亮黄色双层描边和立体投影；主标题下方压一条手绘毛笔刷质感的亮黄色横条，
上面写深蓝色粗体中文副标题「{副标题}」。整体深蓝+亮黄+白高对比，专业短视频封面，
构图饱满，人物与文字有前后层次交叠。不要任何水印。
```
- 横版：`{版式}=16:9横版`、`{人物位置}=右侧，约占画面一半宽度`、`{标题区描述}=左侧超大号、极粗、略微倾斜的中文立体艺术字`
- 竖版：`{版式}=9:16竖版`、`{人物位置}=下半部`、`{标题区描述}=上方超大号、极粗、略微倾斜的中文立体艺术字`

**每张必做三步**：
1. **逐字核中文**：裁文字区放大看图，与主/副标题逐字比对；长文案错字风险上升，不核就交等于没做。
2. **去水印**：右下角有「AI生成 WORKBUDDY」水印 → 裁掉底部 70px，再用 `Image.LANCZOS` 拉回原尺寸（实测无痕、手臂自然）。**禁止用平移覆盖**，会在人像手臂上留横向色带。
3. **精确落位**：按目标比例居中裁切 + resize 到精确像素（生图时已按该方向构图，只修边缘、不切人像），按固定文件名放进视频独立文件夹。

| 用途 | 比例 | 目标尺寸 | 文件名 |
|---|---|---|---|
| 通用横屏 | 16:9 | 1920x1080 | `封面_横屏.png` |
| 通用竖屏 | 9:16 | 1080x1920 | `封面_竖屏.png` |
| 微信视频号个人主页卡片 | 3:4 | 1080x1440 | `封面_视频号个人页3-4.png` |
| 微信视频号分享卡片 | 4:3 | 1440x1080 | `封面_视频号分享4-3.png` |

客观限制（要如实告诉用户）：单张约 5–10 生图积分，四比例是四次生成；人物每次可能略有差异，无法保证四张是"同一姿势"；中文需逐张核字。因此封面这一段不是全自动，也不该假装是。

## 依赖与就绪检查

`auto_clip.py` 每次先跑 `cli.py doctor` 自检：FFmpeg/ffprobe、whisper-local、remotion-gold 缺一即停，不静默降级、不联网上传、不产生云费用。
- Python 依赖：`openpyxl`、`Pillow`、`rembg`、`onnxruntime`（均已装；pip 用阿里云源 `-i https://mirrors.aliyun.com/pypi/simple/`）。
- **关键坑**：build 暗金动画要用 powershell 建 node_modules junction，本机 PATH 只有 System32 没有 PowerShell 目录 → `auto_clip.py` 的 `child_env()` 已注入，勿删。
- 暗金动画依赖 Node + `~/.talking-edit/deps/gold-motion-v1`（已就绪）。
- rembg 首次用会下载 u2netp 模型（~4.7MB）到用户目录（仅备选方案需要）。

## 去重判定（Excel `剪辑记录.xlsx`）

- 表头：源文件名 / 相对路径 / SHA256 / 源时长 / 状态 / 成片路径 / 动画段数 / 耗时 / 完成时间 / 备注。
- `done` 且成片文件仍存在 → 跳过；`failed` 或成片丢失 → 自动重试。
- 判重键 = 相对路径 + SHA256：同名内容变了会重剪；改名视为新条目。
- 一条失败不影响其他，失败原因写进表。封面不参与判重，封面缺失时可单独重跑第 3 段。

## 边界与安全

- 不删除草稿/成片/旧封面/旧风格；不改动口播工作台六步流程和风格注册表。
- `--force` 会覆盖成片/封面，运行前确认。`assets/` 里的风格锚/人物锚**只读，不许替换成个人头像目录的照片**；抠图结果写缓存目录。
- 锚工程 `.auto-clip-anchor`、抠图缓存 `.cover-cache` 都在成片目录内，扫描时自动排除。
- 不把 Key、用户隐私写进仓库或提示词。
