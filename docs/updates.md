# 版本、更新与作者自动发布

## 用户启动更新

`python scripts/workbench.py check-update`返回JSON；preview和skill入口也会在启动前检查。由Git fetch读取固定官方origin/main，不接受任意网页给出的更新地址。

- 相同提交：继续当前版本。
- 官方提交是当前HEAD的后继：尝试Git快进合并，更新VERSION和源码。
- 本地修改未触及上游更新文件：Git通常可以保留修改并快进；有重叠修改/未跟踪文件占位则拒绝更新，保持原文件。
- 自己提交过代码导致分叉：保留本地历史，停止自动更新。
- 自定义分支、不同origin、ZIP无Git、网络不可用：保留原版并给出状态。
- 包装器启动的活动会话：保留当前源码，待会话结束再更新；崩溃的进程锁由操作系统释放。

不承诺对任意自改代码自动兼容。Git能保护文件，不保证用户改动与新API语义兼容；需适配的冲突交给用户/Agent审阅。无本地冲突时版本文件随官方提交同步，有冲突时不能同时强求版本一致和保留所有改动。

建议把用户素材/项目和自定义配置放包外，自有扩展可放忽略的user/目录；该目录首版只是保留区，尚非自动加载插件接口。不要手改VERSION来伪装完成升级。标签固定安装可切到对应tag并使用--no-update。

包装器保护自己启动的命令/预览，不跟踪用户绕过包装器启动的所有外部程序。Agent在更新前先结束当前子Skill后台审阅服务、暂停制作任务并保留原单，更新后重新读取Skill；不在未知云任务中途更换版本。

## 版本约定

首发0.1.0-prototype.1；当前原型通道自动发布每批源码修改增加末尾序号。手动提高序号也支持，禁止倒退。自动提交不自动创建GitHub Release；正式里程碑另打tag。README显示首发阶段，运行时以VERSION和commit为准。

## 作者电脑自动上传（普通用户不要启用）

```sh
python scripts/install_author_watch.py
```

这是显式启用的Windows作者维护功能。注册当前用户登录任务92k-VideoWorkbench-AutoPublish，隐藏运行pythonw；仅监听当前仓库文件事件，连续30秒无修改后合并发布。登录启动对账一次；无周期目录扫描。不会为其他安装者默认启用。

每次发布：检查源码白名单和可能凭据→增加VERSION→普通Git提交→push main→远端提交核对。配置、锁和日志位于用户LOCALAPPDATA/92k-video-workbench下，按仓库路径隔离，不进入Git。没有源码变化就不增加版本；网络失败保留本地提交，在下一次文件变动或登录时重试，不强推。

只接受该官方origin和main。新路径超出白名单、疑似凭据、分支不符或推送失败会停止，日志记录原因，不能把失败当作已上传。扫描是防误传的辅助，作者仍需确保新代码/文本可公开；通用规则无法识别所有私密业务信息。

暂停/卸载：`python scripts/install_author_watch.py --uninstall`。手动发布：`python scripts/publish.py --message "具体修改说明"`。规则代码位于scripts/publish.py；新增合法文件类型时先审查再调整白名单。
